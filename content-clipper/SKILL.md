# content-clipper

把 B站视频、小红书帖子等内容抓下来，转成结构化 Markdown 笔记，落到项目里的
`clips/` 目录。

**这个 skill 不是「复制链接」，而是「读懂内容，并整理成能复习的学习笔记」**：
视频会转录语音、读关键画面，图文帖会解读长文截图与信息图，最终产出一份
**以主旨为纲、按知识逻辑展开、可回头复习**的 Obsidian 笔记，并留下来源证据。

> **这是项目级 skill，需要手动加载。**
> - Claude Code 用 `/content-clipper` 调用
> - OpenCode 里直接说出 `content-clipper` 这个名字
> - 两个客户端都**不会自动触发**（frontmatter 里已关闭）

## 适用与不适用

**适用**：用户给出 B站视频链接/BV 号，或小红书帖子链接，要求总结、整理、收藏、
归档、**学懂并复习**。

**不适用**：只要标题不要内容（不必走完整流程）；纯本地文件处理（不走抓取步骤）。

## 步骤 0：环境自检（必做）

**本 skill 不提供 Python 环境，也不假定它装在哪。先复用项目里已有的环境**：
先看项目根有没有 `.venv/`（或其他已建环境），有就直接激活并复用，不必重建。

**缺依赖时先向用户说明缺什么、装到哪个环境、为什么需要，得到同意再装；
不要擅自安装依赖或工具。** 需要新装时可参考：

```powershell
# 在项目根建环境（名称随意，下面统一用 .venv 举例）
uv venv .venv
uv pip install --python .venv\Scripts\python.exe Pillow numpy faster-whisper

# 需要 GPU 加速转录时，额外装 CUDA 运行库
uv pip install --python .venv\Scripts\python.exe nvidia-cublas-cu12 nvidia-cudnn-cu12

# 激活
.venv\Scripts\Activate.ps1
```

外部命令依赖（**只检测存在性，不要把变量值打印到输出或笔记里**）：

| 依赖 | 检测 | 缺失处理 |
|------|------|---------|
| Python 3.10+ | `python --version` | 先装并激活环境 |
| ffmpeg / ffprobe | `Get-Command ffmpeg` | `winget install Gyan.FFmpeg` |
| BBDown（仅 B站） | `Get-Command BBDown` | `winget install nilaoda.BBDown` |
| curl | `Get-Command curl.exe` | Windows 10+ 自带 |
| `VISION_API_KEY` | 判断变量是否已设置（不为空），**不回显其值** | 画面理解需要；未设置则跳过并说明 |
| `VISION_BASE_URL` | 判断变量是否已设置（不为空），**不回显其值** | 画面理解需要；无默认端点，配置方式见 `references/vision-usage.md` |
| 视觉模型 | `--model` 或 `$env:VISION_MODEL` | 选择当前接口可用且支持图片输入的模型；无默认值，选择规则见 `references/vision-usage.md` |

> ⚠️ **凭据与变量**：变量值一律**在进程内注入**（如临时设置环境变量），
> **不要自动读取 `.env` 文件**，也不要把变量的值写进命令输出、日志或笔记。
> 需要核对时只报告“已设置/未设置”。

> ⚠️ **CUDA 库陷阱**：`pip` 装的 nvidia 库不会自动进 PATH，转录前需要：
> ```powershell
> # 注意取 [1]：venv 下 getsitepackages() 返回 [venv根, venv\Lib\site-packages]，
> # nvidia 库在后者里，取 [0] 会拼不到路径。
> $sp = (python -c "import site; print(site.getsitepackages()[1])")
> $nv = Get-ChildItem "$sp\nvidia" -Directory -ErrorAction SilentlyContinue |
>       ForEach-Object { "$($_.FullName)\bin" }
> $env:PATH = ($nv -join ';') + ";$env:PATH"
> ```
> 报 `cublas64_12.dll is not found` 就是这一步没做。

> winget 新装的命令行工具对**已打开的 shell 不可见**，报「找不到 xxx」时重开终端即可。

### 路径约定（重要）

`scripts/` 与 `references/` 都是**相对本 SKILL.md 所在目录**的。执行脚本前，
要先切到 skill 目录，否则 `python scripts/vision.py` 会因为工作目录不对而找不到文件：

```powershell
# 切到 skill 目录（Claude Code / OpenCode 的项目级挂载点）
cd <项目>\.claude\skills\content-clipper

# 或直接用变量的方式，避免记路径
$skill = "<项目>\.claude\skills\content-clipper"
python "$skill\scripts\vision.py" ...
```

本文档后面所有 `python scripts/xxx.py` 都**默认当前目录是 skill 目录**。

## 步骤 1：识别来源

从链接判断平台，决定后续读取哪份参考：

| 链接特征 | 平台 | 需读参考 |
|---------|------|---------|
| `bilibili.com/video/BV...` 或 `BV` 号 | B站 | `references/platform-bilibili.md` |
| `xiaohongshu.com` / `xhslink.com` | 小红书 | `references/platform-xhs.md` |

> ⚠️ **平台抓取细节必须读参考文件，不要凭记忆推断参数。**
> 两个平台的抓取方式完全不同，参数与常见错误都记在对应 reference 里。

## 步骤 2：抓取内容

按下表拿到「原始素材」——B站要元数据+字幕，小红书要帖子正文+图片。

| 平台 | 目标 | 方法（详见对应 reference） |
|------|------|--------------------------|
| B站 | 元数据（标题/UP主/时长/互动） | 公开 view API |
| B站 | 字幕 | **BBDown**（`--skip-ai false`） |
| 小红书 | 正文与图片列表 | cookies + 页面 `__INITIAL_STATE__` |
| 小红书 | 视频帖字幕 | 平台内嵌字幕优先 |

**关键判断**：BBDown 跑完没有字幕文件、且 `--only-show-info` 里只有视频轨和
音频轨 —— 说明**该视频没有 AI 字幕**（不是工具失败），**不要重试**，进入步骤 3。

抓取结果统一落到一个临时工作目录，后续步骤都在那里处理。

## 步骤 3：转录（无字幕时）

当视频既无平台字幕、也无 UP 主上传字幕，而用户需要正文内容时，用音频转录。

**流程**（三小步）：

```powershell
# 1. 下载音频（B站用 BBDown；小红书见其 reference）
BBDown "<视频URL>" --audio-only --work-dir "<临时目录>"

# 2. 转 16k 单声道 wav
ffmpeg -y -i "<音频>" -vn -acodec pcm_s16le -ar 16000 -ac 1 "<临时目录>\audio.wav"

# 3. 转录（前提：已激活环境；用 CUDA 时先按步骤 0 把 nvidia 库加进 PATH）
python scripts/transcribe.py "<临时目录>\audio.wav" --model small --output "<临时目录>\transcript.txt"
```

**性能提示**：长视频转录耗时受模型、设备与音频长度影响；CUDA 可用时通常比 CPU 快，
先用短音频确认环境和语言设置，再处理长视频。

**何时不该转录**：纯画面/纯 BGM 无解说；用户只想要标题级信息；视频超长且用户未明确要求。

**转录后**：small 模型对专有名词有误差（实测 `SQLite`→`C口`、`PostgreSQL`→`PulseGray`），
整理笔记时应结合标题、标签、**实际画面**和上下文**相互校验修正**。

## 步骤 4：画面理解（补充字幕之外的信息）

字幕只记录「说了什么」，而技术内容的关键常在**画面上**——代码、架构图、PPT、演示界面。

```powershell
$env:VISION_API_KEY = "<你的 key>"
$env:VISION_BASE_URL = "<服务商提供的基础地址>"
$env:VISION_MODEL = "<当前接口可用的视觉模型 ID>"

# 1. 抽帧（均匀采样 + 清晰度筛选）
python scripts/vision.py frames "<视频>" --outdir "<帧目录>" --count 30

# 2. 逐帧解读（文字 + 图示关系 + 要点）
python scripts/vision.py understand "<帧目录>" --batch --output "<临时目录>\frames.txt"
```

> ⚠️ **解读前先读 `references/vision-usage.md`**：里面有抽帧策略的依据、
> 参数含义，以及「为什么不能按场景分数选帧」的实测原因。不要凭直觉调参。

**何时启用**：有代码演示、图表讲解、架构设计、教程操作；或字幕提到「如图」但字幕本身没有内容。

**何时跳过**：纯口播访谈、播客类；已有高质量字幕且不涉及图表。

## 步骤 5：生成笔记

把三份材料合并：**元数据 + 转录/字幕 + 画面解读**，产出到 `clips/<平台>/`。

**默认格式是 Obsidian 学习笔记**：区块结构与语法见 `references/note-template-obsidian.md`；
**讲解怎么写见 `references/learning-note-writing.md`——生成笔记前必读，不是可选**。
区块顺序：**标题 → 主旨 → 展开讲解（正文主线）→ 可选查阅 → 回顾要点 → 来源附件**。
按下面顺序做（细则以 `learning-note-writing.md` 为准，不在这里重复）：

**5.1 定读者与骨架**：默认读者**不掌握这份材料的专有术语**，不假设专业背景；用户已交代背景就以用户为准，**不必每次重新追问**。
内部列出核心问题与前置概念，并**内部盘点所有主题**（正文只展开主线；次要主题在「可选查阅」用**一句索引**交代，不能无声丢掉）。
**按素材性质选讲法**：操作 / 代码演示围绕一个任务推进（小段代码保留、名录进附件）、观点围绕主张与适用边界、
理论 / 因果区分作者解释与已证依据；篇幅与层级跟理解任务相称，短素材一条主线够用就不填满模板。

**5.2 先写讲解主线**：先读懂并核对材料，再起草主线（成文顺序：来源核对在前、证据呈现后置），用连续文字讲通「问题 → 怎么解决 / 依据 → 结论」再补证据。
术语首次出现先讲功能后给名字，**为解释它引入的词也必须可理解**（不需要精确部件名就用功能描述，名录放补充），且**解释有止点**：
只讲支撑当前推理的必要前提，部件名 / 语法 / 推导进补充，不把整门学科展开；材料前提太高又不能短解释时，明示本篇能解释的范围与需另学的前置知识。
例子 / 类比标为**教学例子**，来源没说原因的**就写没说明原因**；标题要有判断支撑；纯观点**标注归属**；按知识逻辑分节，不按转录顺序流水账。

**5.3 分层**：正文只放主线与**理解主线必需**的数据 / 图；详细配置、全量成绩表、奖励系数、旧稿纠错记录进补充层（可折叠 callout 或 `visual-notes.md`）并**留可达指针**。
影响结论的边界条件与重大不确定性**保持正文可见、不折叠**；**没有增量的区块（回顾、可选查阅）省略或合并，不占标题**。

**5.4 数字、表格与图**：**最小充分证据**——一对对照能说明趋势就不搬全榜，删掉只影响复现细节的数字进补充；保留的数字说明**它测什么**、这组差异**能 / 不能推出什么**。
表格只做已解释维度的横向比较，**不代替第一次讲概念**；教学计算与作者实验值分开，未知精确原因不凑。
画面解读补进相关小节，图注用**可见文字**写出这张图说明了什么、支撑什么（材料能证明时才写「证明」）。

**5.5 来源与可信度纪律**：标注**字幕来源**（平台字幕 / 本地转录 / 无字幕）。OCR 与语音识别**都可能出错**，关键数字、专有名词、结论要**对应到来源文本或截图**核对（转录专有名词误差按步骤 3 校验）。
只有掌握可靠时间信息时才写时间戳，**禁止用 frame 编号反推时间**；实在无法确定的标「待核实」或省略，**不能虚构来源标签**。
**来源忠实 ≠ 事实可靠**：重要 / 争议 / 带普遍性的断言就近标出是作者提出或视频声称及未核限制，段落归属可覆盖连续转述、不重复免责声明。
**篇首总声明不给后文兜底**（写了「多为作者观点」不等于后文可写「必然 / 证明 / 就是定义」）；歧义或疑似用词错保持归属并标待核，不替它编定义讲圆、不把类比升格定理。
**逐字稿作附件**（存为步骤 6 的来源证据文件，不进正文）。

**5.6 完成关卡（读者审稿 → 回写）**：每节回答**在解决什么问题、依据是什么、为什么能 / 不能得出这个结论**（只用于自查；材料没有因果依据的不要求捏造）。初稿完成后**换读者视角单独审稿一轮**（**用户允许且工具可用**时用独立子 Agent，否则自审并说明限度），逐条写「原句 / 卡点词 → 为什么卡 → 改成哪句或移到哪层」，**不能只声明符合规范**。
这是**内部审稿记录**，不把整张表或合规清单塞进最终笔记，最终笔记只呈现读者需要的正文、依据与必要不确定性；表列名、外来缩写、部件名要真的教过，与核心问题无关的核对细节移补充；图注必须是正文可见文字，不能只有 `alt`。
**出现未解释的表列名、非必要专业名录、正文无关核对 warning，一律不能交付**；也不设每次交付审批——用户认可的讲法直接执行，首次改变读者层级或用户反馈读不懂时才做一次短节校准。

**完成标准（步骤 5 结束时应满足；任一条不满足即返工，不能交付）**：
1. 主线可读：**只读主旨与展开讲解**就能看懂，不需要跳表、翻附件或查百科。
2. 每一节都能回答 5.6 三问；关键概念有解释、关键因果有交代。
3. 数字通过最小充分证据检查；表格没有代替第一次讲概念；图注用可见文字写出了这张图说明了什么、支撑什么。
4. 过关前必查：主线没有被实现细节淹没、没有重复的边界提醒、解释没有新增未经证实的因果或定义。
5. 三层分层清楚（移出的细节有指针且可达、重大待核实项可见）；引用依据已定位、冲突已标记、无占位符残留（`{{...}}`、空章节等）。

**无转录时**：按实际有的画面来源说明笔记能覆盖到什么范围，**标题与描述不能当成完整
内容**；材料不足以成篇时，输出**「待补全」标记**并说明缺什么，而不是硬凑一份看起来完整
的笔记。

## 步骤 6：保存与索引

### 6.1 笔记文件

- 存到 `clips/<平台>/<日期> <短标题>.md`。
- **日期**：优先用内容**原发布时间**（B站 `pubdate`、小红书 `time`）；确实拿不到
  时用整理当日，并在笔记里**标注这个日期是什么含义**（发布日 / 整理日）。
- **短标题**：简短、可辨、术语不被截断；**不做「≤15 字」的硬性截断**，只要求
  是合法的 Windows 文件名（去掉 `\ / : * ? " < > |`）。

### 6.2 来源证据目录

在 `clips/<平台>/assets/<笔记文件名不含 .md>/` 保存来源证据（细则见
`references/note-template-obsidian.md`）：`source.txt`（实际使用的字幕/带时间戳转录）、
`visual-notes.md`（实际支撑笔记的视觉解读，**用到的图片必须一并保留并链接**）、
少量关键图。**有素材才建，没有就不建、不摆占位**；正文用相对链接（含空格用 `<>`）。
`source.txt` 保留原始记录，术语修正在笔记正文**记录依据与具体位置**，不冒充原话。

### 6.3 索引

更新同目录的 `📋 索引.md`：**按日期倒序**，每行
`- [[笔记名]] — 核心洞察 \`#标签\``。
- 双链 `[[...]]` 的**目标必须准确**（对应真实存在的笔记文件名）。
- **同一内容**的已有条目**更新而不重复**；**不同内容即使同一天也分别保留**。
- 笔记文件名冲突时按**可辨识来源 ID**（BV 号 / 帖子 ID）消歧；**用户手写内容不覆盖**。

### 6.4 清理

- **用户手动放进去的内容一律不可覆盖**。
- 重跑时**只清理自己产生的临时文件**。
- 清理前**先把要保留的附件复制到位并验证链接可打开**，确认无误后再删除临时下载与候选帧。
- **音视频默认作临时原素材，不随笔记归档；`.env` 不得作为附件。**

**完成标准（步骤 6 结束时应满足；任一条不满足即返工，不能交付）**：
1. 笔记文件与 `assets/` 均按约定落盘；文件名合法、日期含义已标；**无素材时不强建空目录**。
2. 正文里引用的附件相对链接**实际存在且可打开**（不是占位路径）。
3. 索引条目双链目标准确、日期倒序、无重复条目。
4. 本轮临时文件已清理，用户既有内容未被误删。

## ⚠️ 维护须知

- **默认笔记格式是 Obsidian 学习笔记**：区块与语法规则在
  `references/note-template-obsidian.md`，讲解质量规则在
  `references/learning-note-writing.md`；改哪一类规则就改对应文件，不要在两处写同一规则
- **生成笔记前必读 `references/learning-note-writing.md`**：步骤 5 的 5.1–5.6 都指向它；
  它不是可选参考，删掉会让步骤 5 退回只有泛化要求
- **不要改回「按场景分数选帧」**：实测教程类视频 scene 分数极低（P99 仅 0.03），
  且高分段是过渡帧（运动模糊），最不适合读图。详见 `references/vision-usage.md`
- **不要退化成纯 OCR**：`understand` 默认解读图示关系与要点，`--raw` 仅在确需纯文字时用
- **平台参数以 reference 为准**：BBDown 的 `--skip-ai false` 等参数可能随版本变化
- 改动任何平台抓取逻辑，同步更新对应 `references/platform-*.md`
- **规划或实施后续代码改造时，先读 `references/development-plan.md`**（日常生成笔记不必读）
