# 学习笔记写法（正文怎么写才算讲懂）

本文件是「笔记写到什么程度才算讲懂」的**唯一规则出处**。主 SKILL.md 步骤 5 生成笔记前
**必读**本文件；`references/note-template-obsidian.md` 只管区块结构与 Obsidian 语法，不管讲解质量。

**默认读者**：对这份材料的专有领域**不熟**。规则不假设他有专业背景，也不假设他认识材料
里的缩写和行话。用户已交代过自己的背景时，以用户的交代为准，**不必每次重新追问**。

**这不是摘要**：摘要把内容变少，学习笔记把内容变好懂。长素材可以按主题拆成多节，
但主线层要比原材料更容易读懂。

---
## 一、动笔前：先想清楚要讲懂什么

1. **列出核心问题**：在内部列出「读完这篇，读者应能自己解释」的**少数**核心问题
   （通常 2–5 个），以及解释它们所需的**前置概念**。这是笔记的骨架。
2. **内部盘点主题**（不是正文逐项复述）：所有主题过一遍并记住，正文只展开主线；主线之外的次要主题在「可选查阅」层用**一句索引**交代（不必都写成段落），不能无声丢掉。
3. **按素材性质选讲法**（选择提示，不是三套死模板）：操作 / 代码演示围绕一个任务推进，必要的小段代码保留、实现名录进附件；观点围绕主张、理由与适用边界，不硬塞实验或技术式机制；理论 / 因果区分作者的解释与已证依据。正文篇幅与层级跟理解任务相称——短素材一条主线讲清就够，不为了填满模板硬撑。
4. **先写不依赖表格的讲解主线**：先读懂并核对材料，再起草解释主线——讲的是**成文顺序**（来源核对在动笔前完成、证据呈现后置）；用连续文字把「问题 → 怎么解决 → 为什么成立」讲通，而不是先摆一张表再补解释。跳过这几步直接排小标题，最容易产出一份「结构完整但读不懂」的笔记。

---
## 二、正文怎么写：从具体问题讲到结论

**第一段（主旨）**：先给**具体的问题**和**为什么值得关心**，再给结论。结论必须由材料
支撑；材料没说的，不替它下判断。

**引入术语**：术语第一次出现时先说明**它做什么、在材料里起什么作用**，再给名字（「SFT＝监督微调」只是翻译，不算讲懂）。**前置依赖检查**：为解释它引入的每个词本身也要可理解，不需要精确部件名时**用功能描述**，名录放补充。
**解释有止点**：只讲支撑当前推理的必要前提；不影响理解主线的部件名、语法、推导放补充，不为「不查百科」把整门学科展开（「默认读者不懂专有术语」≠ 从「电脑是什么」讲起）。材料本身前提很高又不能短解释时，**明示本篇能解释的范围与需另学的前置知识**，不假装零基础全懂，也不拿空泛口号顶替重要机制。

**推理过渡**：段落之间要有「为什么讲到这里」的过渡，让读者跟得上下一步。**不要每节套
同一个问答模板**——「为什么 / 怎么做 / 例子 / 边界」按材料实际有没有覆盖，没有的别硬凑。

**例子与因果**：必要的例子和类比帮助理解，但要**标明是教学例子**，不能让读者误以为材料
做过这个实验。**不虚构实验因果**：材料没说原因时就写「材料没有说明原因」，不要补一个
顺理成章但没依据的因果。

**段落纪律**：一段讲一个意思；并列的信息用列表，不要挤进长段落。

**来源忠实 ≠ 事实可靠**：**重要、有争议、或带普遍性的断言**就近标出是作者提出 / 视频声称及未核限制；连续转述可用一句段落归属覆盖（如「作者接着给出三步」），不必每句「作者说」，也不要重复多遍免责声明。**篇首总声明不能给后文兜底**——写了「以下多为作者观点」不等于后文可以写「必然 / 证明 / 就是定义」。来源有歧义或疑似用词错时保持归属并标「待核实」，**不替它编一个定义讲圆**，**不把类比升格成定理**；整理补充的基础释义要有把握，复杂或冲突的事实需额外可靠来源才定论，没核不装核。

## 三、三层信息：正文 / 补充 / 来源

| 层 | 放什么 | 读者怎么遇到 |
|----|--------|-------------|
| **正文** | 讲解主线，以及**理解主线必需**的数据、图 | 直接读，不用跳转 |
| **补充**（可折叠 callout 或 `visual-notes.md`） | 详细配置、全量成绩表、奖励系数、旧稿纠错记录等**核对用**细节 | 需要核对时才展开 |
| **来源** | 原始链接、来源证据（`source.txt`、图） | 要核对真实性时才看 |

判据：**读正文不应该需要跳到表格、附件，或去查百科，才能看懂主线**；附件用来核对「正文说的是不是真的」，不是理解正文的前提。

**移出去的细节必须可达**：正文对应位置留一句指针（「完整配比见补充」「逐条奖励见 `visual-notes.md`」），不能移走之后连去哪找都不说。

**必须留在正文可见的**：影响结论的边界条件、重大不确定性、待核实项，这些**不折叠**；只有轻微的补充说明才折叠。**正文不是审计报告**：核对清单、逐项状态、旧稿纠错对照一律进补充层，正文只讲主线。

## 四、数字、表格与图：只留改变判断的

**最小充分证据**：先问「说明这条结论，最少要哪几个数」。能用**一对对照**说明趋势就不搬全榜——论证「更小不必然分数更低」，只要作者同一项测试上两个版本的对照，五档三指标的完整成绩表放补充或附件；删掉只影响复现细节的数字同样放补充。保留的数字先说明**它测的是什么**、这组差异**能 / 不能推出什么**；「可核」是进附件核对的条件，不是「必须进正文」的理由。

**教学计算 ≠ 作者实验值**：用自拟小例子演示算法——模型保存的 4 个数（称权重），三个用 3 bit、一个用 8 bit，平均 4.25 bit——必须标为**自拟、非作者配方**；作者的实测值（如文件 BPW 5.07）还受权重位宽以外的元数据与编码开销影响，**不掌握精确分解就不要倒推**。

**表格的用法**：表格用来对**已经解释过的维度**做横向比较（同一批指标横向看谁好）。**不要用表格代替第一次讲概念**——读者还没被告知「这是什么」，表里的列名就只是黑话。

**图**：图注要用**正文可见的文字**写出这张图说明了什么、支撑什么（只写 `alt` 不算；材料确实能证明时才写「证明」）；选图是因为它支撑某个判断，图注就把那个判断说出来。

## 五、坏例子 → 好例子

**坏例子**（记录是真的，但缺概念与推理）：

```markdown
| 阶段 | 记录 | 结果 |
|------|------|------|
| SFT | 1,905 条，239 步，采用中途 P50 | — |
| 第二周 RLVR | 同题 8 答，留一基线 | GPQA 未恢复，未采用该轮权重 |
| SimPO | 110 对 / 73 题，5 步 | 科学、代码小幅改善，通识小幅回落 |
```

问题在哪：这些记录本身是真的，**缺的是概念与推理**——P50、GPQA、「留一基线」都没有解释；
为什么 SFT 要走中途版本、为什么第二周那轮权重没被采用、什么算「改善」，全靠读者自己猜。
表格并列摆开却没有主线说明每阶段在解决什么、为什么进入下一步、结论能管到哪里。**这不是数据不对，是讲解缺失。**

**好例子**（先讲问题与因果，细节退到补充）：

```markdown
## 训练流程：从「不肯交卷」到把行为与能力分开评估

作者先讲了一个观察：模型有时推理写得很长，却始终不给最终答案。

**第一步，拿好回答当示范。** 作者用一批好的完整回答做示范，训练去调整模型参数，让它
更倾向于学到的这种回答方式。这一阶段叫 **SFT（监督微调）**——它学的对象是作者准备好的
好回答，不是让模型自己试错。

**第二步，让模型自己答，再按结果给反馈。** 作者让模型自己作答，然后按两点给反馈：
答得对不对，以及有没有正常把答案交出来。这里要分清两件事——**把答案交出来（交卷）**
和 **答案是对的（答对）** 不是同一件事。

*（打个比方：学生交了卷，不等于题目做对了。这是帮助理解的**教学类比**，不是作者做过
的实验。）*

**第三步，第二周做了实验，结果没达到采用标准。** 这一轮之后，模型在固定检查题上更会
提交了，但在科学推理测试（GPQA）上的能力没有恢复，所以作者**没有采用这一轮训练出的模型版本**。

**第四步，回到中途的 SFT 版本做偏好训练。** 作者取回 SFT 中途保存的模型版本，用同一
问题下的好回答与失败回答做偏好训练（**SimPO**），让模型更倾向于同题的好回答而少走失败
路径。据作者报告，科学、代码类小幅改善，通识类小幅回落。

**结论**：训练让行为变了，不等于达到了采用标准；**行为与能力要分别评估**。

完整配置与奖励系数见补充。
```

好例子补上的正是这些概念与推理：每一步在解决什么问题、为什么进入下一步、结论能管到哪里；配置与系数退到补充层，读者读完主线就能复述这条链。

## 六、跨主题短例（避免只会写 LLM 题材）

**主题：文件压缩与运行内存**（教学例子，非实验）。不要一上来写「ZIP 是无损压缩，压缩率
取决于信息熵」就结束。先给具体问题——你把一堆文件打包发走，对方解压后要能用；再说清「打包
压缩」是把重复内容换成更短的记号，所以体积变小；然后才引入**无损压缩**：解压后和原来逐字节
一样，代价是使用前要先解压。最后点出容易混的地方：**文件占磁盘小**和**程序运行时占内存少**
是两件事——压缩包省的是存储，程序跑起来占用的是内存，文件变小不等于跑起来更轻。

## 七、完成关卡：读者审稿 → 回写

**逐节关卡**：每节回答「在解决什么问题 / 依据是什么 / 为什么能或不能得出这个结论」（材料没有因果依据的不要求捏造；只用于自查，不要求正文照此排列）。**过关前必查**：一条主线是否被实现细节淹没；是否有重复的边界提醒（概览、每段、单独小节、末尾 warning 说同一声明就合并）；解释里是否新增了未经证实的因果或定义。

**读者审稿（单独一轮）**：初稿写完后换读者视角单独过一遍——用户允许且工具可用时用独立子 Agent，否则自审，并在报告里说明自审的限度（不强制依赖工具）。审稿逐条落成**内部记录表**（该表与合规清单只用于内部审稿，**不塞进最终学习笔记**；最终笔记只呈现读者需要的正文、依据与必要不确定性），**不能只声明符合规范**：

| 正文原句 / 卡点词 | 读者为什么卡 | 改成什么 / 移到哪层 |
|---|---|---|
| 「大型状态投影」 | 没教过，不知道指什么 | 换功能描述，或整段移补充 |
| 表头 GPQA / MMLU / LCB | 三列都没解释，看不出各测什么 | 先在正文说明各测什么；与主线无关就移补充 |

查三件事：**外来缩写、部件名、表格列名是否真的教过**（只出现一次又没解释＝没教过）；**与本篇核心问题无关**的核对细节、待核实项移进补充层（重大可信度项仍留正文可见）；**图注是正文可见文字，不能只有 `alt`**。

**回写与重过**：审稿发现的真问题要改回正文再重过一遍。阅读质量以**用户反馈**最终校准，AI 审稿通过不等于读者读懂；不设每次交付都要用户审批——用户认可的讲法直接执行，只有首次改变读者层级、或用户反馈读不懂时，才做一次短节校准。

## 八、与模板的分工

区块顺序：**正文主线 → 可选查阅 → 回顾要点 → 来源附件**（详见 `references/note-template-obsidian.md`）。
四类区块**按需出现**：没有增量就省略或合并——回顾只是复述正文、可选查阅没有实际内容时，不占标题；附件与来源仍要可达。本文件管「内容有没有讲懂」，模板文件管「区块长什么样、Obsidian 语法对不对」；冲突时讲解质量优先，改模板去适配。
