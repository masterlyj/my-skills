# 项目 QA 记忆整理

把**一个代码项目**的材料，整理成**能被记住、能被复述**的 QA。用途是面试、答辩和考试。

## 先明确一件事：这是为了背，不是为了查

这份材料的唯一目标是**把它装进脑子**。决定外部记录是否损害记忆的，不是"记不记笔记"，而是**有没有带着"要把它装进脑子"的明确目标**——带着这个目标整理，损害几乎可以被抵消。

由此推出三条贯穿全文的做法：

- **正文写成能直接讲出来的话**，不写"详见某处"。
- **合上材料能讲出来，才算整理完。** "读着很熟"不算数：材料在眼前时产生的熟悉感会让人高估掌握程度，而这种高估在闭卷时会暴露。
- **正文不放代码符号**（行号、变量名、函数名、key 名）。这不是因为有研究证明符号有害，而是一个工程判断：背的时候你会卡在符号上，而不是卡在理解上。出处单独放证据层（见下）。

## 适用范围

**用于**：为一个代码项目建立或维护 `qa/` 目录，把源码、配置、数据、设计文档里的事实改写成问答。

**不用于**：

- 只回答单个简单问题 —— 直接回答即可。
- 与代码项目无关的材料（理论学习、论文、流程制度）—— 四段式是为"问答本身就是材料原生形态"的场景设计的，套到论证链或条件表型材料上会强制一次有损转换。
- 评价候选人、打分或给录用建议。

## 与项目文档的分工

| | 项目文档（README / docs / repo-docs） | 本 Skill 产出的 `qa/` |
| --- | --- | --- |
| 回答什么 | "这个系统怎么工作" | "我能不能记住并讲清楚" |
| 组织方式 | 按模块和数据流 | 按**记忆地图**，同一层一个维度 |
| 成功标准 | 说明完整 | **合上材料能讲出来** |

不要照搬文档目录。同一个事实，文档里是机制说明，这里必须变成"能背下来的一段话"。

## 铁律

1. **合上材料能讲出来才算整理完。** 写不出 1–3 句核心答案，说明还没真正理解——回去把材料读懂，而不是把文档抄长。
2. **展开必须写出"为什么"。** 见下方【展开说明】——这是四段式不退化成摘要的关键。
3. **锚点要有区分度。** 见下方【关键词锚点】——雷同的锚点会主动削弱记忆。
4. **正文零符号。** 四段正文里不出现行号、变量名、函数名、key 名；出处单独放证据层。
5. **一个分类轴贯穿同一层。** 混用维度会让记忆地图失效。
6. **不编造事实。** 材料没写的不要补；说法冲突或没把握的，标 `[待确认]`。
7. **证据必须可追。** 每条结论都要能翻到出处，且出处会随代码漂移——所以必须按触发条件回来复核。

## 金字塔结构

三层，各司其职。**先背顶层，再用顶层定位下层。**

```text
qa/README.md              ← 顶层：定位 + 记忆地图 + 文件索引
   ├─ 域 1 ─────────────→  01-xxx.md   中观：域范围 + 四段式 Q&A + 证据索引
   ├─ 域 2 ─────────────→  02-xxx.md
   └─ 域 3 ─────────────→  03-xxx.md
```

| 层 | 在哪 | 承载什么 | 记忆要求 |
| --- | --- | --- | --- |
| 顶层 | `README.md` | 一句话定位 + 域清单 + 文件索引 | **要背** |
| 中观 | 每个域文件 | 域范围说明 + 域内 Q&A + 证据索引 | 记住"这个域有哪些问题" |
| 微观 | 每条 Q&A | 四段式答案 | 记核心答案与关键词 |

**为什么顶层要背**：层级结构本身的作用是充当**回忆时的检索计划**——先想起有哪几块，再从块里找具体答案。它不是一个需要额外背诵的目录，而是你回忆时的抓手。

这也决定了**顶层不要扇出过多**：一个挂着一二十个子项的顶层节点，本身就是一个弱线索（一个线索关联的项目越多，通过它回忆越难）。

### 顶层：`qa/README.md`

打开目录的第一眼就是它，所以它承担金字塔的顶点。**只放三样东西：定位、地图、文件索引。**

```markdown
# <项目名> QA

> <1–2 句：这个项目是什么，这份材料覆盖哪几块>

## 记忆地图

1. <域一> —— <一句话范围>
2. <域二> —— <一句话范围>
3. <域三> —— <一句话范围>

## 文件索引

| 文件 | 覆盖什么 | 什么时候翻 |
| --- | --- | --- |
| [00-facts.md](00-facts.md) | 数字、名词、上线状态 | 上场前查数字 |
| [01-xxx.md](01-xxx.md) | <域一范围> | <什么情况下翻它> |
| [02-xxx.md](02-xxx.md) | <域二范围> | <什么情况下翻它> |

## 复核记录

| 日期 | 触发原因 | 复核范围 | 结论 |
| --- | --- | --- | --- |

## 待确认

- [待确认] <缺什么>（影响：<哪条结论>）
```

要求：

- 地图**只到域这一层**，每个域一句话范围。**不要在这里逐条列出 Q 标题**——那会把地图淹掉，也会和域文件里的标题形成双份维护。
- 文件索引到**文件**这一层，说明每个文件覆盖什么、什么时候翻它。
- **不写任何答案正文。** README 变长就是在往这里抄内容，立刻拆回域文件。

### 中观：每个域一个文件

- 文件顶部写一句**域范围**，说明这个域收什么、不收什么。
- 接着按顺序写该域的 Q&A，每条一个 `###` 小节，四段式。
- 文件末尾放**证据索引**（见下）。
- 域与文件**一一对应**，不要一个域跨两个文件，也不要一个文件塞两个域。

> 文件划分是**整理结构**，不是复习顺序。复习时按域交错、打乱顺序抽，不要从头到尾顺读——顺读时你会从上下文猜出答案，那种"答对了"不算数。

### 微观：每条问答的四段

顺序固定，不可增减、不可换位。

```markdown
### <简短问题标题>

【Q】<独立、明确的问题>

【核心答案】
<1–3 句费曼式答案。合上材料也能独立复述。>

【展开说明】
- <为什么是这样——至少一条原文没明写的推论>
- <做法或过程>
- <示例、边界、例外>

【关键词锚点】
关键词1 · 关键词2 · 关键词3 · 关键词4
```

#### 【Q】问题

- 一个问题只问一件事；多个意图就拆成多条。
- 写成自然语言疑问句，接近真实的问法。
- **只合并纯措辞重复的问法**（"什么是幂等"和"幂等是什么意思"）。同一个事实的**不同入口各留一条**（定义向"什么是幂等"、因果向"为什么需要幂等"）——换个角度再问一遍几乎没有害处，反而多一个回忆入口。把别名收进关键词锚点即可。
- 要警惕的不是"重复"，而是**两条容易被互相混淆的近似问答**：它们会互相干扰。发现这种就合并或明确写出区别。

#### 【核心答案】

这是**最需要打磨**的一段。

- 1–3 句，先给结论。
- 用最朴素的话讲清"是什么、为什么、怎么做"，假设听的人不懂术语。
- 必须能脱离展开说明独立成立。写完遮住展开自测一遍。
- 不用循环定义，不用空泛口号，不只换一种说法复述问题。
- 无法简化的术语，首次出现时用半句话解释。
- **保持短，但不要为了短而抽掉实质。** 把关键阈值、公式挪走之后，如果核心答案变成了没有可检验内容的摘要，那它已经失去价值。

> 关于"费曼式"：这个词指的是**用自己的话把机制讲清楚**，它的价值在这一点上，而不是某个有名有姓的方法。不要把它当成有研究背书的技术来宣称。

#### 【展开说明】

**这一段的核心职责不是补充细节，而是写出"为什么"。**

- **至少写出一条原文没有明写、需要你自己推出来的步骤**（因果链、设计动机、条件推导）。为什么这条最重要：理解产生的增量**恰好集中在需要推断的地方**——对材料已明写的内容，多讲一遍和复述没有区别；只有把隐含的推理显式写出来，才算真的消化了。
- 反过来说：如果展开只是把核心答案换个说法讲长，那四段式就退化成了"做摘要"，而摘要是公认低效的学习动作。
- 只展开理解核心答案所必需的内容，按"为什么 → 做法 → 示例 → 边界"分点；没有对应内容就省略。
- 保留关键条件、因果关系和**少而硬的数字**，能记住的才写。
- 说法冲突时并列写出，标 `[待确认]`，不要静默拼成一个结论。

#### 【关键词锚点】

```text
幂等 · 结果缓存 · 分布式锁 · 重复处理
```

- 写**回忆线索**：术语、别名、英文名、缩写、相关概念，通常 3–6 个。
- **关键要求：锚点之间要有区分度。** 同一个线索关联的条目越多，通过它回忆越弱；如果十条问答都挂同一个大词（比如都写"幂等"），那个线索就废了。让每条的关键词指得出**这一条特有的是什么**。
- 用材料原本的语言，不要为了格式统一去音译或生造英文。
- 不用写 ID、编号或路径。
- 写完自测：**只看这一行，能不能把答案想起来**。想不起来就把缺的那个线索补上。
- 如果几条 Q&A 天然共享一个主题，可以在域范围说明里写清它们的关系和区别——把关系讲出来能缓解线索互相干扰。

> 关键词作为记忆钩子有用，但别指望它承担长期保持。真正让记忆留下来的是下面那条：**闭卷自测**。

## 两层材料：正文与证据

**正文四段零符号**（背的时候用），**证据单独一层**（被追问"你怎么知道的"时用）。

每个域文件末尾放该文件的证据索引，按 Q 编号列出出处：

```markdown
## 证据索引

- Q1 → `README.md:3`、`repo-docs/walkthroughs/one-real-run.md:3-7`
- Q2 → `app/service.py:1194-1238`、`clients/email_forwarder.py:36-54`
```

- 只写 Q 编号，**不重复 Q 标题**（标题在正文里已经有了）。
- 一个 Q 对多个出处时全部列出。
- `00-facts.md` 这类事实页例外：它本来就是查数字用的，符号多是**对的**，出处直接标在表里，不必另开证据段。

## 自测：怎么算真的记住了

**自测必须闭卷、隔天、口述。** 这三条缺一不可：

| 要求 | 为什么 |
| --- | --- |
| **闭卷** | 材料在眼前时的熟悉感会让人高估自己，那种"我都会"在考场上会碎掉 |
| **隔天** | 刚整理完就自测，测的是短期流畅，不是长期记住 |
| **口述** | 出声或写出来，才暴露"以为自己懂但讲不出"的地方 |

做法：合上全部文件，只看 README 的地图，逐个域自问"这里有哪些问题"，再对每条尝试讲出核心答案和"为什么"。讲不顺的回去重读材料——**不要靠重读自己的笔记来解决**。

顺带一个好消息：**讲错不算白费**。带着正确答案的检索（哪怕是失败的检索）比不检索记得更牢；而这份 QA 本身自带答案，正好提供了反馈。所以放心大胆地先答再看。

## 复核：证据会腐坏，必须回来查

证据层引用的是**会变的代码**。不写复核规则，它一两个月就烂掉，比不写更危险。

**触发条件**（满足任一即复核）：

- 被引用的代码、配置或数据发生改动。
- 上线状态变化（某个功能从"默认关闭"变成"灰度中"或反之）。
- 数字类结论过期（统计窗口滚动、样本量变化）。
- 每轮面试/答辩/考试前。
- 距上次复核超过 3 个月。

**怎么复核**：

1. 按证据索引逐个打开出处，确认结论仍然成立。
2. 数字重新对一次口径（窗口、分母、样本量），不要沿用旧值。
3. 发现结论已变：改正文与证据；**改变结论的旧值不要静默替换**，在复核记录里留一行。
4. 发现出处已消失（文件被删、函数被改名）：标 `[待确认]`，不要凭记忆改写。
5. 在 README 的**复核记录**表里登记：日期、触发原因、复核范围、结论。

## 工作流

思考是自下而上的，写作是自上而下的。**先读透材料，再定地图，最后填内容。**

### 新建

1. **读材料，别急着分类。** 读入口文件、配置、数据、已有文档。目标只有一个：**能用自己的话说出这个项目在干什么**。说不出来就继续读——这一步偷懒，后面全是抄文档。
2. **列问题清单**（内部完成，不写入输出）：提取显式与隐含问题；把藏了多个意图的问法拆开；只合并纯措辞重复的；剔除只在细节层面成立、不值得记忆的；留下**真正会被问到、且值得记住**的。
3. **定地图，先写 README。** 按下面的规则定域、写范围、把问题归位。地图没定就写域文件，必然返工。
4. **逐条写四段。** 先写核心答案，再补展开。顺序不能反——先写展开很容易变成抄文档；而展开里**必须落到"为什么"**，这往往要求你回源码再确认一次因果关系。
5. **回填证据索引**，逐个核对出处真实存在。
6. **自测**（按上面的闭卷隔天口述做）。

### 更新已有 `qa/`

1. **定位归属域。** 新内容先归到已有的域；确实放不进再考虑新增域——新增域要同步改 README 地图与文件索引。
2. **判断动作**：
   - 已有 Q 覆盖了这个问法（纯措辞重复）→ 只补关键词线索。
   - 是新的独立问题，或同一事实的**另一个入口** → 在所属域内追加，并补它的证据索引。
   - 材料变了导致答案过时 → 改核心答案与展开，**命中下面复核的触发条件**。
   - 内容已失效 → 删除该条，并清掉它的证据索引行。
3. **保持原有顺序与域划分**，只增补内容。重排会破坏肌肉记忆。
4. **主动标出缺口**：更新时发现的冲突或缺失，写进 README 的"待确认"，不要静默补一个看似合理的答案。

## 分类轴怎么选

顶层分类不是文件柜，是**脑子里那张地图**。先定轴，再填内容。

**同一个层只用一个维度。** 代码项目默认按**问题性质**切：

| 域 | 收什么 |
| --- | --- |
| 主链路 / 架构 | 项目做什么、请求怎么走、为什么这么设计 |
| 技术核心 | 项目里最有技术含量的那一块（模型、并发、算法、存储） |
| 业务规则 | 领域概念、边界条件、容易答错的细节 |
| 运维与风险 | 可观测性、上线与回滚、事故复盘、遗留问题、协作边界 |

要求：

- **顶层 3–5 个域**。多到记不住就说明切得太细。
- **每个域 5–10 条 Q**。明显超出就按同一轴再拆一层或拆域；只有两三条就并进相邻域。
- 归不进任何域 → 检查是轴选错了，还是这条不该收。
- 无法可靠归类 → 单独放"其他"，不要硬塞。

### 自测

遮住内容，只看 README 的地图，逐条问自己："这个域里有哪些问题？" 答不上来就调整分类，而不是硬背。

## 文件组织

```text
qa/
  README.md         顶层：定位 + 记忆地图 + 文件索引 + 复核记录
  00-facts.md       数字与状态（可选，按需）
  01-<域>.md        域文件：域范围 + 四段式 Q&A + 证据索引
  02-<域>.md
  03-<域>.md
```

- 编号可选但推荐：它固定了整理顺序，也让新增域时有位置可插。
- 域文件名包含域名本身，不要只叫 `01.md`。
- 允许按需增加专项文件（数字速查、术语表、简历素材），条件是：在 README 文件索引里登记，且不重复四段正文。

## 质量检查

**可机械核对的：**

- [ ] README 里没有 Q 标题，只有域列表和文件索引。
- [ ] README 里没有任何答案正文。
- [ ] 顶层 3–5 个域，每个域大致 5–10 条 Q，域与文件一一对应。
- [ ] 每个域文件末尾有证据索引，Q 编号与正文一一对应，没有多余或缺失。
- [ ] 每条 Q&A 都按【Q】→【核心答案】→【展开说明】→【关键词锚点】排列。
- [ ] 正文四段里没有行号、变量名、函数名、key 名。

## 这些规则的依据

留着这一节是为了以后改 skill 时不要过度声称。**标"强"的可以当结论用，标"经验/工程"的不要写成有研究证明。**

| 规则 | 依据强度 |
| --- | --- |
| 合上材料能讲出来才算完成 | **强**：闭卷检索显著优于重读；重读会提高信心但不提高长期保持 |
| 自测要闭卷 + 隔天 | **强**：同上。刚学完的熟悉感不可信 |
| 展开必须写出"为什么" | **强**：自我解释的增量只出现在需要推断的地方 |
| 锚点要有区分度 | **强**：一个线索关联的条目越多，回忆越弱 |
| 讲错不算白费 | **强**（有反馈时）：失败检索配正确答案仍有效 |
| 一个分类轴贯穿同一层 | **间接**：层级作为检索计划有效；但层级本身不保证收益 |
| 顶层 3–5 域、每域 5–10 条 | **经验**：与工作记忆容量（约 4 个组块）量级相容，无直接实验 |
| 一个问题只问一件事 | **经验**：未见对照实验，属实践共识 |
| 只合并纯措辞重复 | **经验**：同一事实换角度看没有害处；有害的是易混淆的近似条目 |
| 正文零符号 | **工程判断**：无实验比较，理由是降低无关负荷 |
| "费曼式" | **弱**：名称源自 2011 年博客，无对照实验。保留这个词是因为它指"用自己的话讲清"，不当作有研究背书的方法 |

**不要写进 skill 的说法**（流行但证据薄弱或已被推翻）：7±2（实为约 4）、"讲给孩子听"有效（有反证）、"收藏会损害学习"、"笔胜于键盘"、"Google 效应"、间隔固定为某比例。
