# 项目 QA 记忆整理

把**一个代码项目**的材料，整理成**能被记住、能被复述**的 QA。

用途是面试、答辩和考试。整理的终点不是"写全"，而是**合上材料后还能讲出来**。

## 适用范围

**用于**：为一个代码项目建立或维护 `qa/` 目录，把源码、配置、数据、设计文档里的事实改写成问答。

**不用于**：

- 只回答单个简单问题 —— 直接回答即可。
- 与代码项目无关的材料（理论学习、论文、流程制度）—— 四段式是为"问答本身就是材料原生形态"的场景设计的，套到论证链或条件表型材料上会强制一次有损转换。
- 评价候选人、打分或给录用建议。

## 与项目文档的分工

| | 项目文档（README / docs / repo-docs） | 本 Skill 产出的 `qa/` |
| --- | --- | --- |
| 回答什么 | "这个系统怎么工作" | "我能不能记住并讲清楚" |
| 组织方式 | 按模块和数据流 | 按**记忆地图**，同一层一个维度 |
| 成功标准 | 说明完整 | **能被复述**，关键词能唤起答案 |

不要照搬文档目录。同一个事实，文档里是机制说明，这里必须变成"能背下来的一段话"。

## 铁律

1. **能背下来才算整理完。** 写不出 1–3 句核心答案，就说明还没真正理解——回去把材料读懂，而不是把文档抄长。
2. **正文零符号。** 四段正文里不出现行号、变量名、函数名、key 名。它们会让人卡在符号上。出处单独放证据层。
3. **证据必须可追。** 每条结论都要能翻到出处，且出处会随代码漂移——所以必须按下面的触发条件回来复核。
4. **不编造事实。** 材料没写的不要补；说法冲突或没把握的，标 `[待确认]`。
5. **一个分类轴贯穿同一层。** 混用维度会让记忆地图失效。
6. **关键词锚点只服务于回忆。** 它的唯一职责是"看到它能把答案勾出来"，不承担定位、去重等工程职责。

## 金字塔结构

三层，各司其职。**先背顶层，再用顶层定位下层。**

```text
qa/README.md              ← 顶层：定位 + 记忆地图 + 文件索引
   ├─ 域 1 ─────────────→  01-xxx.md   中观：域范围 + 四段式 Q&A + 证据索引
   ├─ 域 2 ─────────────→  02-xxx.md
   └─ 域 3 ─────────────→  03-xxx.md
```

| 层 | 在哪 | 承载什么 | 记忆要求 |
| --- | --- | --- | --- |
| 顶层 | `README.md` | 一句话定位 + 域清单 + 文件索引 | **要背** |
| 中观 | 每个域文件 | 域范围说明 + 域内 Q&A + 证据索引 | 记住"这个域有哪些问题" |
| 微观 | 每条 Q&A | 四段式答案 | 记核心答案与关键词 |

### 顶层：`qa/README.md`

打开目录的第一眼就是它，所以它承担金字塔的顶点。**只放三样东西：定位、地图、文件索引。**

```markdown
# <项目名> QA

> <1–2 句：这个项目是什么，这份材料覆盖哪几块>

## 记忆地图

1. <域一> —— <一句话范围>
2. <域二> —— <一句话范围>
3. <域三> —— <一句话范围>

## 文件索引

| 文件 | 覆盖什么 | 什么时候翻 |
| --- | --- | --- |
| [00-facts.md](00-facts.md) | 数字、名词、上线状态 | 上场前查数字 |
| [01-xxx.md](01-xxx.md) | <域一范围> | <什么情况下翻它> |
| [02-xxx.md](02-xxx.md) | <域二范围> | <什么情况下翻它> |

## 复核记录

| 日期 | 触发原因 | 复核范围 | 结论 |
| --- | --- | --- | --- |

## 待确认

- [待确认] <缺什么>（影响：<哪条结论>）
```

要求：

- 地图**只到域这一层**，每个域一句话范围。**不要在这里逐条列出 Q 标题**——那会把地图淹掉，也会和域文件里的标题形成双份维护。
- 文件索引到**文件**这一层，说明每个文件覆盖什么、什么时候翻它。
- **不写任何答案正文。** README 变长就是在往这里抄内容，立刻拆回域文件。

### 中观：每个域一个文件

- 文件顶部写一句**域范围**，说明这个域收什么、不收什么。
- 接着按顺序写该域的 Q&A，每条一个 `###` 小节，四段式。
- 文件末尾放**证据索引**（见下）。
- 域与文件**一一对应**，不要一个域跨两个文件，也不要一个文件塞两个域。

### 微观：每条问答的四段

顺序固定，不可增减、不可换位。

```markdown
### <简短问题标题>

【Q】<独立、明确的问题>

【核心答案】
<1–3 句费曼式答案。合上材料也能独立复述。>

【展开说明】
- <原理或依据>
- <做法或过程>
- <示例、边界、例外>

【关键词锚点】
关键词1 · 关键词2 · 关键词3 · 关键词4
```

#### 【Q】问题

- 一个问题只问一件事；多个意图就拆成多条。
- 写成自然语言疑问句，接近真实的问法。
- 相似问法合并成一条，把别名收进关键词锚点。

#### 【核心答案】

这是**最需要打磨**的一段。

- 1–3 句，先给结论。
- 费曼式：假设听的人不懂术语，用最朴素的话讲清"是什么、为什么、怎么做"。
- 必须能脱离展开说明独立成立。写完遮住展开自测一遍。
- 不用循环定义，不用空泛口号，不只换一种说法复述问题。
- 无法简化的术语，首次出现时用半句话解释。

#### 【展开说明】

- 只展开理解核心答案所必需的内容。
- 优先按"原理 → 做法 → 示例 → 边界"分点；没有对应内容就省略。
- 分点是为了好记，不是为了写长。**价值密度在核心答案，不在展开**。
- 保留关键条件、因果关系和**少而硬的数字**，能记住的才写。
- 说法冲突时并列写出，标 `[待确认]`，不要静默拼成一个结论。

#### 【关键词锚点】

```text
幂等 · 结果缓存 · 分布式锁 · 重复处理
```

- 写**回忆线索**：术语、别名、英文名、缩写、相关概念，通常 3–6 个。
- 用材料原本的语言，不要为了格式统一去音译或生造英文。
- 不用写 ID、编号或路径 —— 锚点是给你自己看的记忆钩子，不承担任何定位职责。
- 写完自测：**只看这一行，能不能把答案想起来**。想不起来就把缺的那个线索补上。

## 两层材料：正文与证据

**正文四段零符号**（记忆用），**证据单独一层**（被追问时用）。

每个域文件末尾放该文件的证据索引，按 Q 编号列出出处：

```markdown
## 证据索引

- Q1 → `README.md:3`、`repo-docs/walkthroughs/one-real-run.md:3-7`
- Q2 → `app/service.py:1194-1238`、`clients/email_forwarder.py:36-54`
```

- 只写 Q 编号，**不重复 Q 标题**（标题在正文里已经有了）。
- 一个 Q 对多个出处时全部列出。
- `00-facts.md` 这类事实页例外：它本来就是查数字用的，符号多是**对的**，出处直接标在表里，不必另开证据段。

## 复核：证据会腐坏，必须回来查

证据层引用的是**会变的代码**。不写复核规则，它一两个月就烂掉，比不写更危险。

**触发条件**（满足任一即复核）：

- 被引用的代码、配置或数据发生改动。
- 上线状态变化（某个功能从"默认关闭"变成"灰度中"或反之）。
- 数字类结论过期（统计窗口滚动、样本量变化）。
- 每轮面试/答辩/考试前。
- 距上次复核超过 3 个月。

**怎么复核**：

1. 按证据索引逐个打开出处，确认结论仍然成立。
2. 数字重新对一次口径（窗口、分母、样本量），不要沿用旧值。
3. 发现结论已变：改正文与证据；**改变结论的旧值不要静默替换**，在复核记录里留一行。
4. 发现出处已消失（文件被删、函数被改名）：标 `[待确认]`，不要凭记忆改写。
5. 在 README 的**复核记录**表里登记：日期、触发原因、复核范围、结论。

## 工作流

思考是自下而上的，写作是自上而下的。**先读透材料，再定地图，最后填内容。**

### 新建

1. **读材料，别急着分类。** 读入口文件、配置、数据、已有文档。目标只有一个：**能用自己的话说出这个项目在干什么**。说不出来就继续读——这一步偷懒，后面全是抄文档。
2. **列问题清单**（内部完成，不写入输出）：提取显式与隐含问题；把藏了多个意图的问法拆开；合并语义等价的；剔除只在细节层面成立、不值得记忆的；留下**真正会被问到、且值得记住**的。
3. **定地图，先写 README。** 按下面的规则定域、写范围、把问题归位。地图没定就写域文件，必然返工。
4. **逐条写四段。** 先写核心答案，再补展开。顺序不能反——先写展开很容易变成抄文档。
5. **回填证据索引**，逐个核对出处真实存在。
6. **自测**（见下方质量检查）。

### 更新已有 `qa/`

1. **定位归属域。** 新内容先归到已有的域；确实放不进再考虑新增域——新增域要同步改 README 地图与文件索引。
2. **判断动作**：
   - 已有 Q 覆盖了这个问法 → 只补关键词线索。
   - 是新的独立问题 → 在所属域内追加，并补它的证据索引。
   - 材料变了导致答案过时 → 改核心答案与展开，**命中下面复核的触发条件**。
   - 内容已失效 → 删除该条，并清掉它的证据索引行。
3. **保持原有顺序与域划分**，只增补内容。重排会破坏肌肉记忆。
4. **主动标出缺口**：更新时发现的冲突或缺失，写进 README 的"待确认"，不要静默补一个看似合理的答案。

## 分类轴怎么选

顶层分类不是文件柜，是**脑子里那张地图**。先定轴，再填内容。

**同一个层只用一个维度。** 代码项目默认按**问题性质**切：

| 域 | 收什么 |
| --- | --- |
| 主链路 / 架构 | 项目做什么、请求怎么走、为什么这么设计 |
| 技术核心 | 项目里最有技术含量的那一块（模型、并发、算法、存储） |
| 业务规则 | 领域概念、边界条件、容易答错的细节 |
| 运维与风险 | 可观测性、上线与回滚、事故复盘、遗留问题、协作边界 |

要求：

- **顶层 3–5 个域**。多到记不住就说明切得太细。
- **每个域 5–10 条 Q**。明显超出就按同一轴再拆一层或拆域；只有两三条就并进相邻域。
- 归不进任何域 → 检查是轴选错了，还是这条不该收。
- 无法可靠归类 → 单独放"其他"，不要硬塞。

### 自测

遮住内容，只看 README 的地图，逐条问自己："这个域里有哪些问题？" 答不上来就调整分类，而不是硬背。

## 文件组织

```text
qa/
  README.md         顶层：定位 + 记忆地图 + 文件索引 + 复核记录
  00-facts.md       数字与状态（可选，按需）
  01-<域>.md        域文件：域范围 + 四段式 Q&A + 证据索引
  02-<域>.md
  03-<域>.md
```

- 编号可选但推荐：它固定了背诵顺序，也让新增域时有位置可插。
- 域文件名包含域名本身，不要只叫 `01.md`。
- 允许按需增加专项文件（数字速查、术语表、简历素材），条件是：在 README 文件索引里登记，且不重复四段正文。

## 质量检查

**可机械核对的：**

- [ ] README 里没有 Q 标题，只有域列表和文件索引。
- [ ] README 里没有任何答案正文。
- [ ] 顶层 3–5 个域，每个域大致 5–10 条 Q，域与文件一一对应。
- [ ] 每个域文件末尾有证据索引，Q 编号与正文一一对应，没有多余或缺失。
- [ ] 每条 Q&A 都按【Q】→【核心答案】→【展开说明】→【关键词锚点】排列。
- [ ] 正文四段里没有行号、变量名、函数名、key 名。
- [ ] **同一条结论里的数字在全文出现多次时完全一致。**
- [ ] 不确定的结论标了 `[待确认]`。
- [ ] README 的文件索引与实际文件一致，没有死链。

**需要自己判断的：**

- [ ] 只看 README 的地图，能说出每个域有哪些问题。
- [ ] 每条核心答案遮住展开后仍能独立复述。
- [ ] 只看关键词锚点，能把对应的答案想起来。
- [ ] 同一层只有一个分类维度，没有混用。
- [ ] 展开说明里没有为了凑长度而写的段落。
- [ ] 复核记录里最近一次复核仍在有效期内。
