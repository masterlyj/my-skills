# 项目答辩 QA 库

为**一个具体项目**建立 QA 库，让项目负责人被问到任何问题时能立刻答上来，并且答案指得到证据。

输入是一个项目（当前工作区或用户指定的仓库）；输出是该项目里的 `qa/` 目录。这不是"把零散问答归类"，而是**从源码里挖事实，再改写成回答**。

## 与普通文档的分工

| | 项目文档（README / docs / repo-docs） | 本 Skill 产出的 `qa/` |
| --- | --- | --- |
| 回答什么 | "这个系统是怎么工作的" | "被问到你怎么答" |
| 组织方式 | 按系统模块和数据流 | 按**面试官的提问路径** |
| 事实要求 | 说明机制 | 每个结论都要有 `file:line` |
| 独有价值 | 新人上手 | 查出**文档与源码不一致**，并给出可背的口径 |

不要复制项目文档的目录结构。同一个事实，文档里是"机制说明"，这里必须是"回答 + 证据"。

## 铁律

1. **没有证据的答案不要写进来。** 每条结论后面必须有文件加行号，或可复现的实测数据。
2. **答案与源码冲突时以源码为准**，并在事实卡末尾的漂移清单里记一笔。文档漂移清单往往是这个库最有价值的产出。
3. **不编造数字。** 没有实测就标 `[待回填]`，不确定就标 `[需确认]`。宁可留空，不许估。
4. **上线状态逐项标注。** 这是最容易被抓的字段：写完的代码、默认关闭的功能、只在测试环境验证过的能力，三者不能混为一谈。
5. **口语稿里不出现代码符号。** 看到变量名、key 名、函数名就换成白话，否则上场会卡在符号上。

## 两层材料，不能混着用

| | 口语稿 | 证据稿 |
| --- | --- | --- |
| 在哪 | `06-cheatsheet.md` | `00-facts.md` 与其余各页 |
| 长什么样 | 零代码符号，每句可直接念 | 含变量名、行号、key 名 |
| 什么时候用 | 上场前 5 分钟，或对着人练 | 准备阶段；被追问"你怎么知道的"时翻 |
| 要不要背 | 要，逐句念顺 | 不用背，能翻到就行 |

两层都要产出。只有证据稿，上场会卡符号；只有口语稿，一被追问就露底。

## 顶层分类只是入口

分类的用途是**导航**，不是知识结构本身。真正的结构在每条问答内部。

分类轴**按面试官的提问路径**切，通常落在四个主题域：

1. **主链路 / 架构** —— "介绍下你的项目""为什么这么设计""一封请求走哪些步骤"
2. **技术亮点** —— 项目里最有技术含量的那一块（模型、并发、检索、算法……）
3. **业务难点** —— 领域规则、边界条件、易错点
4. **运维 / 事故 / 协作** —— 可观测性、事故复盘、团队边界、遗留风险

再按项目自身特点增补，例如简历素材单独成页。**不要按难度、按代码模块、按文件夹分类**——面试官不按这些提问。

## 每条问答的四层结构

这是本 Skill 的核心产物。每条问答固定四层，顺序不可换：

```markdown
## Q<N>. <面试官会怎么问>

**① 一句话答案**
> <先甩结论。1–3 句，可直接开口念。>

**② 展开**
<讲清 why 和机制。可以放表格、分点。这里是"面试官点头后继续说完"的内容。>

**追问雷达**
- "<他接下来最可能问什么？>" → <怎么答>
- "<还会问什么？>" → <怎么答>

**证据索引**
- <结论> → `path/to/file.py:120-135`
- <另一个结论> → `repo-docs/modules/xxx.md:5-7`
```

**追问雷达是这个库最值钱的部分。** 答辩翻车通常在第二问——第一问靠背，第二问靠准备。每个 Q 至少列 2 条追问，优先列：

- 数字类追问（"多少？""占比呢？"）
- 边界类追问（"那如果失败了怎么办？"）
- 质疑类追问（"为什么要这么复杂？""能不能简化？"）
- 归属类追问（"这是你做的吗？"）

**① 一句话答案**必须能脱离 ② 独立回答问题。写完后遮住 ② 自测一遍。

## 事实卡 `00-facts.md`

上场前查数字用的，**符号多是正确的，不要口语化**。分节并逐项标注可信度：

- `[源码已确认]` —— 可以直接说
- `[实测]` —— 附口径（时间窗口、分母、样本量）
- `[待回填]` / `[需确认]` —— **不许随口说**

必备内容：

| 节 | 内容 |
| --- | --- |
| 一句话定位 | 这个项目做什么，一句话 |
| 基本盘 | 应用 ID、语言框架、入口、部署形态 |
| 运行形态 | 有几个进程、分别干什么、防重怎么做 |
| 核心枚举 | 原因码 / 状态机 / 类型表等，**标注"设计几个 / 实测触发几个"** |
| 拦截点 | 进主流程前有几道闸，哪些落表哪些只打日志 |
| 关键 key / 配置 | 存储 key、TTL、配置项、模型名 |
| 外部依赖 | 服务码、接口用途 |
| 上线状态 | **逐项**标注：生产在用 / 已落地未上生产 / 仅测试环境 |
| 效果数据 | 指标 + 口径 + 出处 |
| 易错点 | 容易被答错的点，用引用块单独拎出来 |
| 文档漂移清单 | 文档说法 vs 源码实际 + 位置 |

**数字必须带口径。** 只答结论会被追问"怎么算的"；给出窗口、分母、样本量才显得有数据意识。

## 口语稿 `06-cheatsheet.md`

固定六节：

1. **开场** —— 背下来，30 秒讲完项目是什么 + 一个核心数字
2. **必答问题** —— 5 个左右，每个一段可直接念的回答
3. **高频追问** —— 一句话挡回去
4. **收尾金句** —— 一句能留下印象的总结
5. **绝对不能说的话** —— 表格：别说 / 为什么
6. **被问到不知道的怎么办** —— 标准话术，并重申"不要现编"

**禁语清单很重要**：把"默认关闭的功能说成已上线""把估算说成实测""记错口径"这类高危表述列出来。它比正面答案更能防翻车。

## 工作流

### 1. 勘察项目，确认边界

先确认这个项目**是什么、边界在哪**：读 `README`、入口文件、配置文件、数据目录、已有文档（`docs/`、`repo-docs/`）。

产出一句话定位和一张"基本盘"表。定位写不出来就说明还没看够，继续读。

### 2. 建证据基座

把事实按主题聚成表，每条带 `file:line`。**至少走两遍**：

- 第一遍建立全局印象，列出待核实清单。
- 第二遍逐条回源码核对，尤其是数字、枚举、状态、配置默认值。

区分四类陈述：源码已确认 / 实测数据 / 文档说法 / 未知。**不要把"文档这么写"当成事实。**

### 3. 查漂移

把关键文档与源码逐条对照，专门找不一致：默认值、数量、参数、字段名、异步/同步、编号、状态。

这一步的产出直接进事实卡的漂移清单，并在回答时给出"以源码为准"的口径。**这是本 Skill 相对普通文档的核心增量，不要跳过。**

### 4. 选分类轴，定页数

按提问路径选 3–5 个主题域，每域一页，编号连续（`01-`、`02-`……）。`00-facts.md` 固定是事实卡，最后一页固定是口语稿。

### 5. 写问答页

每页内部按 Q 编号，逐条写四层结构。写 ① 的时候想象面试官刚问完，你要抢第一句。

### 6. 写事实卡与口语稿

先写事实卡（所有数字和状态在这里定稿），再从事实卡和问答页**翻译**出口语稿——不是复制，是去掉所有符号后的重写。

### 7. 写 README 索引

`qa/README.md` 是导航页，至少含：两层材料对照表、每页怎么读、文件索引、速答卡（问 → 一句话答案 → 详解链接）、数据状态与待补项、维护约定。

### 8. 自检

见下方质量检查。

## 输出文件约定

```text
qa/
  README.md         导航：两层材料、每页怎么读、文件索引、速答卡、维护约定
  00-facts.md       事实卡：数字、名词、状态、易错点、文档漂移清单
  01-<主题域>.md    问答页，每条四层结构
  02-<主题域>.md
  ...
  05-resume.md      简历素材（可省略）
  06-cheatsheet.md  口语速答卡：零符号，可逐句念
```

更新已有 `qa/` 时**保持原有编号和页名**，只增补内容，不要重排——用户的肌肉记忆依赖编号。

## 质量检查

交付前逐项确认：

- [ ] 每条结论都有 `file:line` 证据；没有证据的已删除或标为未知。
- [ ] 文档与源码的冲突已登记进漂移清单，并给出"以源码为准"的口径。
- [ ] 所有数字都带口径（窗口、分母、样本量）；没实测的标了 `[待回填]`。
- [ ] 上线状态逐项标注，"代码完成""默认关闭""仅测试环境"没有混为一谈。
- [ ] 每个 Q 的 ① 遮住 ② 后仍能独立回答问题。
- [ ] 每个 Q 至少 2 条追问雷达，且覆盖数字 / 边界 / 质疑 / 归属中至少两类。
- [ ] 口语稿里没有任何代码符号，逐句能念顺。
- [ ] 禁语清单列出了本项目最危险的几种错误表述。
- [ ] 枚举类事实写清了"设计几个 / 实测触发几个"，以及未触发的原因。
- [ ] README 的速答卡与各页内容一致，没有指向已删除的 Q。
