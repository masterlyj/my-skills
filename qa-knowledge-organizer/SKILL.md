# QA 记忆整理

把**一个主题**的材料，整理成**能被记住、能被复述**的 QA。

材料可以是代码项目、一个理论专题、一篇论文、一套流程制度或一场培训。整理的终点不是"写全"，而是**合上材料后还能讲出来**。

## 与项目文档的分工

| | 项目文档（README / docs） | 本 Skill 产出的 `qa/` |
| --- | --- | --- |
| 回答什么 | "这个系统怎么工作" | "我能不能记住并讲清楚" |
| 组织方式 | 按系统模块和数据流 | 按**记忆地图**，同一层一个维度 |
| 成功标准 | 说明完整 | **能被复述**，关键词能唤起答案 |

不要照搬文档目录。同一个事实，文档里是机制说明，这里必须变成"能背下来的一段话"。

## 铁律

1. **能背下来才算整理完。** 写不出 1–3 句核心答案，就说明还没真正理解——回去把材料读懂，而不是把文档抄长。
2. **顶层是地图，不是正文。** `qa/README.md` 只放定位和地图；把答案抄进去会造成双份维护，也会淹掉索引。
3. **正文里不放打断记忆的符号。** 行号、变量名、堆叠的参数值会让人卡在符号上。确需保留的精确值（法规条文号、公式、阈值）集中放附录，不混进四段正文。
4. **不编造事实。** 材料没写的不要补；说法冲突或没把握的，标 `[待确认]`。
5. **一个分类轴贯穿同一层。** 混用维度会让记忆地图失效。
6. **关键词锚点是回忆入口**，不是装饰。写完自测：只看锚点能不能把答案想起来。

## 金字塔结构

三层，各司其职。**先背顶层，再用顶层定位下层。**

```text
qa/README.md              ← 顶层：定位 + 记忆地图（唯一入口，先背这个）
   ├─ 域 1 ─────────────→  01-xxx.md   中观：域范围 + 本域问题清单
   │                          └─ Q1…Qn  微观：四段式答案
   ├─ 域 2 ─────────────→  02-xxx.md
   └─ 域 3 ─────────────→  03-xxx.md
```

| 层 | 在哪 | 承载什么 | 记忆要求 |
| --- | --- | --- | --- |
| 顶层 | `README.md` | 一句话定位 + 域清单 + 每域范围 | **要背**，能在 30 秒内报完 |
| 中观 | 每个域文件 | 域范围说明 + 域内 Q 标题清单 | 记住"这个域有哪些问题" |
| 微观 | 每条 Q&A | 四段式完整答案 | 记核心答案与锚点 |

### 顶层：`qa/README.md`

打开目录的第一眼就是它，所以它承担金字塔的顶点。**只放两样东西：定位和地图。**

```markdown
# <主题名> QA

> <1–3 句：这是什么，这份材料覆盖哪几块>

## 记忆地图

1. [<域一>](01-xxx.md) —— <一句话范围>
2. [<域二>](02-xxx.md) —— <一句话范围>
3. [<域三>](03-xxx.md) —— <一句话范围>

## 索引

- [01-xxx.md](01-xxx.md)
  - Q1 <问题标题>
  - Q2 <问题标题>
- [02-xxx.md](02-xxx.md)
  - Q1 <问题标题>

## 待确认

- [待确认] <缺什么>（影响：<哪条结论>）
```

要求：

- 地图必须能**一口气报完**。报不完就是域太多或范围写得含糊。
- 索引让 README 单独存在时也能定位到每一条 Q，不用打开域文件找。
- **不写任何答案正文。** README 变长就是在往这里抄内容，立刻拆回域文件。
- 额外的专项文件（速查卡、术语表、简历素材、精确值附录）也在这里登记，但同样不放答案正文。

### 中观：每个域一个文件

- 文件顶部写一句**域范围**，说明这个域收什么、不收什么。
- 接着按顺序列该域的 Q，每条一个 `###` 小节。
- 域与文件**一一对应**，不要一个域跨两个文件，也不要一个文件塞两个域。

### 微观：每条问答的四段

顺序固定，不可增减、不可换位。

```markdown
### <简短问题标题>

【Q】<独立、明确、可搜索的问题>

【核心答案】
<1–3 句费曼式答案。合上材料也能独立复述。>

【展开说明】
- <原理或依据>
- <做法或过程>
- <示例、边界、例外>

【关键词锚点】
`<域>/<概念>` · 关键词1 · 关键词2 · 关键词3
```

#### 【Q】问题

- 一个问题只问一件事；多个意图就拆成多条。
- 写成自然语言疑问句，接近真实的问法。
- 相似问法合并成一条，把别名收进关键词锚点。

#### 【核心答案】

这是**最需要打磨**的一段。

- 1–3 句，先给结论。
- 费曼式：假设听的人不懂术语，用最朴素的话讲清"是什么、为什么、怎么做"。
- 必须能脱离展开说明独立成立。写完遮住展开自测一遍。
- 不用循环定义，不用空泛口号，不只换一种说法复述问题。
- 无法简化的术语，首次出现时用半句话解释。

#### 【展开说明】

- 只展开理解核心答案所必需的内容。
- 优先按"原理 → 做法 → 示例 → 边界"分点；没有对应内容就省略。
- 分点是为了好记，不是为了写长。**一份 QA 的价值密度在核心答案，不在展开**。
- 保留关键条件、因果关系、数字；但数字要少而硬，能记住的才写。
- 说法冲突时并列写出，标 `[待确认]`，不要静默拼成一个结论。

#### 【关键词锚点】

```text
`<域>/<概念>` · 关键词1 · 关键词2 · 关键词3
```

- 第一个反引号字段是**稳定 ID**，用于定位和去重，全文唯一。
- ID 用小写英文、数字和连字符，域与概念之间用 `/`，例如 `pipeline/idempotency`。
- 概念含义没变就复用原 ID；不要因为改了标题就换 ID。
- 后续关键词写**回忆线索**：别名、英文名、缩写、相关概念。通常 3–6 个。
- 锚点是给未来的自己用的：看到它应当能想起这条答案。

## 分类轴怎么选

顶层分类不是文件柜，是**脑子里那张地图**。先定轴，再填内容。

**同一个层只用一个维度。** 不要混用"主题 / 难度 / 阶段"。

按材料类型选轴：

| 材料类型 | 建议轴 | 典型域 |
| --- | --- | --- |
| 代码项目 | 问题性质 | 主链路 / 技术核心 / 业务规则 / 运维与风险 |
| 理论学习 | 知识层次 | 基础概念 / 机制原理 / 应用与边界 / 常见误区 |
| 论文研究 | 论证结构 | 问题与动机 / 方法与设计 / 结论与证据 / 局限 |
| 流程制度 | 时间阶段 | 触发与准入 / 正常执行 / 异常处理 / 收尾与复盘 |
| 产品业务 | 角色视角 | 用户 / 运营 / 数据 / 风险 |

域数量与容量：

- **顶层 3–5 个域**，多到记不住就说明切得太细。
- **每个域 5–9 条 Q**。超了就按同一轴再拆一层或拆域；只有两三条就并进相邻域。
- 归不进任何域 → 检查是轴选错了，还是这条不该收。
- 无法可靠归类 → 单独放"其他"，不要硬塞。

### 自测

遮住内容，只看 README 的地图，逐条问自己："这个域里有哪些问题？" 答不上来就调整分类，而不是硬背。

## 文件组织

```text
qa/
  README.md         金字塔顶层：定位 + 地图 + 索引（唯一入口，必建）
  01-<域>.md        域文件，一域一文件
  02-<域>.md
  03-<域>.md
```

- 编号可选但推荐：它固定了背诵顺序，也让新增域时有位置可插。
- 域文件的命名包含域名本身，不要只叫 `01.md`。
- 允许按需增加专项文件（速查卡、术语表、精确值附录等），条件是：在 README 登记，且不重复四段答案正文。

## 工作流

思考是自下而上的，写作是自上而下的。**先读透材料，再定地图，最后填内容。**

### 新建

1. **读材料，别急着分类。** 读入口文件、配置、数据、已有文档，或论文摘要与正文。目标只有一个：**能用自己的话说出这个主题在讲什么**。说不出来就继续读——这一步偷懒，后面全是抄文档。
2. **列问题清单**（内部完成，不写入输出）：提取显式与隐含问题；把藏了多个意图的问法拆开；合并语义等价的；剔除只在细节层面成立、不值得记忆的；留下**真正会被问到、且值得记住**的。
3. **定地图，先写 README。** 按上面的选轴规则定域、写范围、把问题归位。**先写出那句能一口气报完的总结**，再往下写。地图没定就写域文件，必然返工。
4. **逐条写四段。** 先写核心答案，再补展开。顺序不能反——先写展开很容易变成抄文档。核心答案写不顺，说明这条还没理解透，回去查材料。
5. **回填 README 索引**，逐个核对 Q 标题与链接。
6. **自测**（见下方质量检查）。

### 更新已有 `qa/`

1. **定位归属域。** 新内容先归到已有的域；确实放不进再考虑新增域——新增域要同步改 README 地图与编号。
2. **判断动作**：
   - 已有 Q 覆盖了这个问法 → 只补关键词别名，不新开一条。
   - 是新的独立问题 → 在所属域内追加，并回填 README 索引与锚点。
   - 材料变了导致答案过时 → 改核心答案与展开，**锚点 ID 保持不变**。
   - 内容已失效 → 删除该条并清掉 README 索引，不要让死链留下。
3. **保持原有编号与域划分**，只增补内容。重排会破坏肌肉记忆。
4. **主动标出缺口**：更新时发现的冲突或缺失，写进 README 的"待确认"，不要静默补一个看似合理的答案。

## 质量检查

交付前逐项确认：

- [ ] 只看 `qa/README.md`，能在 30 秒内报出完整地图，并说出每个域有哪些问题。
- [ ] README 里没有任何答案正文，只有定位、地图、索引。
- [ ] 顶层 3–5 个域，每个域 5–9 条 Q，域与文件一一对应。
- [ ] 同一层只有一个分类维度，没有混用。
- [ ] 每条 Q 只有一个主要意图；重复问法已合并。
- [ ] 每条都按【Q】→【核心答案】→【展开说明】→【关键词锚点】排列。
- [ ] 每条核心答案遮住展开后仍能独立复述，且不超过 3 句。
- [ ] 正文里没有行号、变量名等打断记忆的符号；精确值已挪到附录。
- [ ] 数字少而硬，且都能说清来历；不确定的标了 `[待确认]`。
- [ ] 每个稳定 ID 全文唯一、格式一致，能代表该条的核心概念。
- [ ] 只看关键词锚点，能把对应的答案想起来。
- [ ] README 索引与域文件里的 Q 标题完全一致，没有死链或漏登记。
- [ ] 展开说明里没有为了凑长度而写的段落。
