# QA 知识整理

把杂乱材料整理成可检索、可复习、可持续维护的结构化 Q&A。默认使用中文输出；用户指定了语言、术语或代码标识符时，保留它们。

## 适用边界

**使用本 Skill：**

- 整理多条面试问答、FAQ、访谈答疑、培训材料或学习笔记。
- 对一批问题做去重、拆分、归类和改写，沉淀为题库或知识库。
- 从长文本、会议记录或多份材料中批量提取 Q&A。

**不要使用本 Skill：**

- 用户只问一个简单问题，且没有整理、归档或批量改写的意图 —— 直接回答即可。
- 用户主要目标是评价候选人、给出录用结论或打分 —— 本 Skill 只整理知识，不做人事判断。
- 来源材料不足以支撑答案时，不要凭常识补造事实。

## 工作流

### 1. 确认目标与证据范围

先识别三件事：读者是谁、用途是什么、输入来自哪里。用户没有说明时，默认产出"可复习、可检索的通用题库"。

只依据用户提供的材料和被明确允许使用的资料整理答案，并区分三类陈述：

- **事实** —— 来源直接支持的内容。
- **推断** —— 能由事实合理推出、但来源未直接陈述的内容，标明"推断："。
- **待确认** —— 缺少依据、说法冲突或无法判断的内容，标明"[待确认]"。

### 2. 建立问题清单

这一步在内部完成，不写入输出。依次执行：

1. 从材料中提取显式问题和隐含问题。
2. 把同时询问多个独立意图的问题拆成多个原子问题。
3. 合并语义等价的问题，保留常见别名或问法。
4. 删除寒暄、口头禅，以及不影响含义的重复表述。
5. 不要因为措辞相似就合并答案边界不同的问题。

### 3. 选择唯一分类轴

顶层分类必须服务于读者的检索目的，并且**在同一层只使用一个维度**。

默认优先级：

1. **主题 / 知识域** —— 适合面试题库、FAQ、学习笔记。
2. **任务流程 / 阶段** —— 适合操作手册、培训材料。
3. **用户旅程 / 角色** —— 适合产品访谈、跨角色答疑。

不要在同一层混用不同轴。例如"Java / 高级题 / 排障"就是三个维度混用："Java" 是主题，"高级题" 是难度，"排障" 是场景。确需表达次要维度时，把它放进关键词或下一级，不要新增并列的顶层类别。

分类要求：

- 分类之间尽量互斥，合起来覆盖当前材料（MECE）。
- 每个原子问题只归入一个主分类。
- 无法可靠归类的内容放进"待归类"，不要硬塞。
- 类别过多时合并相近主题；类别过宽时沿同一轴继续拆分。

### 4. 构建金字塔结构

按"总览 → 分类 → 问题 → 答案"组织：

1. 用 1–3 句话概括整组材料覆盖什么、核心结论是什么。
2. 按重要性或理解顺序排列顶层分类，不要照搬输入顺序。
3. 每个分类先写一句范围说明，再列出对应的 Q&A。
4. 分类内的问题从基础概念递进到机制、实践和边界；不适用时按读者最常用的检索顺序排列。

### 5. 逐条重写 Q&A

#### 【Q】问题

- 改写成独立、明确、可搜索的问题。
- 一个问题只保留一个主要意图。
- 补足必要的上下文，但不改变原意。

#### 【核心答案】

- 用 1–3 句话直接回答，先给结论。
- 用费曼式表达：假设读者不了解术语，用简单语言讲清"它是什么、为什么重要或该怎么做"。
- 无法简化的术语，首次出现时用一句话解释。
- 不要用循环定义、空泛口号，或只是换一种说法复述问题。

#### 【展开说明】

- 只展开理解核心答案所必需的内容。
- 优先按"原理 → 做法 → 示例 → 边界 / 例外"分点；没有对应内容就省略该点。
- 保留重要条件、因果关系、数字和来源差异。
- 遇到冲突答案，分别写出"说法 A / 说法 B / 冲突点"，并标记"[待确认]"；不要静默拼成一个结论。

#### 【关键词锚点】

格式固定为：

```text
`<分类短名>/<概念短名>` · 关键词1 · 关键词2 · 关键词3
```

要求：

- 第一个反引号字段是**稳定 ID**，用于引用和去重，全文唯一。
- ID 使用小写英文、数字和连字符，分类与概念之间用 `/`，例如 `java/concurrent-hash-map`。
- 知识库后续更新时，只要概念含义没变就复用原 ID；不要因为重写标题就改 ID。
- 后续关键词保留原文术语、常用别名、英文名或缩写，通常 3–6 个，不要堆砌整句话。

### 6. 处理重复、冲突和缺口

- **重复问题** —— 合并为一条，并在关键词中保留高价值别名。
- **局部重叠** —— 提取公共结论，但把不同边界分别留在对应问题中。
- **答案冲突** —— 并列展示来源说法和冲突点，标记"[待确认]"。
- **只有问题没有答案** —— 保留问题，在核心答案处写"[待确认] 当前材料未提供答案"。
- **只有陈述没有问题** —— 只有在能忠实反推问题时才转成 Q&A，否则放进末尾的"未转化材料"。
- **来源可追踪** —— 输入带有说话人、文档名、时间或链接时，在展开说明的相关事实后保留简短的来源标记。

## 输出格式

除非用户指定其他格式，严格使用下面的模板。分类标题可以增减，但每条 Q&A 必须完整保留四个字段及其顺序。

```markdown
# <知识库标题>

> <1–3 句总览：覆盖范围、核心结论、材料边界>

## 1. <顶层分类>

<一句话说明该分类的范围>

### 1.1 <简短问题标题>

【Q】<独立、明确的问题>

【核心答案】
<1–3 句费曼式答案。>

【展开说明】
- <原理或依据>
- <做法或过程>
- <示例、边界、例外或来源；没有则省略>

【关键词锚点】
`<category>/<concept>` · <关键词1> · <关键词2> · <关键词3>
```

材料存在缺口时，在正文之后追加：

```markdown
## 待确认事项

- [待确认] <缺失信息或冲突点>（影响：<会影响哪条结论>）
```

不要额外输出"整理思路""内部推理过程"，或没有依据的补充知识。

## 质量检查

交付前逐项确认：

- 顶层分类使用同一个轴，类别之间没有明显重叠，并且覆盖了全部有效问题。
- 每个问题只有一个主要意图；重复问题已合并，多意图问题已拆分。
- 每条都按【Q】→【核心答案】→【展开说明】→【关键词锚点】排列。
- 核心答案脱离展开说明后仍能独立回答问题，且不超过 3 句。
- 展开说明与核心答案一致，包含必要依据、边界和例外，没有凭空扩写。
- 事实、推断和 [待确认] 已明确区分；冲突没有被静默消解。
- 每个稳定 ID 全文唯一、格式一致，并能代表该条知识的核心概念。
- 原始术语、数字、代码标识符和来源信息没有因为润色而失真。
